## 🧠 ML Design Decisions

### URL detection (`url_features.py`)
Extracts a numeric feature vector per URL:
- Domain length, path length, query-string length
- Subdomain depth and count of dots
- Character entropy of the domain (high entropy → likely generated)
- Presence of IP address as hostname
- Count of suspicious keywords (`login`, `verify`, `secure`, `account`, `update`, `bank`, etc.)
- Use of non-standard ports (`:8080`, `:4443`)
- HTTPS vs HTTP flag
- TLD in known-bad list (`.xyz`, `.tk`, `.top`, `.gq`, …)

Classifier: **Random Forest** — handles mixed numeric features without scaling, interpretable feature importances.

### Text detection (`text_features.py`)
Extracts features from email/SMS/chat bodies:
- TF-IDF on word unigrams + bigrams (top 5 000 features)
- Character n-gram TF-IDF (2–4 grams, top 3 000) to catch obfuscation
- Message length, ratio of uppercase chars, count of URLs in body, count of exclamation marks

Classifier: **Logistic Regression** — fast, probabilistic output (confidence score), strong baseline for text.

### Training pipeline (`pipeline.py`)
- `sklearn.pipeline.Pipeline` chains feature union → classifier
- 80/20 stratified train/test split
- Hyperparameter grid search via `GridSearchCV`
- Persisted with `joblib.dump`

## 🔒 Safety & Disclaimer Design

Every prediction surface will carry a **non-guaranteeing disclaimer** ("This tool is intended to assist, not replace, expert judgement. Predictions may be incorrect."). Input validation will:
- Strip/reject oversized inputs (URL > 2 083 chars, message > 10 000 chars)
- Reject non-string types and null inputs with a descriptive error, never a traceback
- Never execute, fetch, or resolve any URL submitted by the user
